# 作業卡 7：登記藥師複核

適用：藥師已完成某些圖卡的醫療複核，要把頁面標記為「已複核」。先讀作業卡 0（共同步驟），再照本卡做。

**藥師在修改圖卡的同一次工作中看過定稿並表示已複核時，不用本卡**，照作業卡 0 第 5 步在原本那筆 CR 登記。本卡用於另外登記的複核，例如舊頁複核完成、或修改已推送後才複核。

**AI 不能自己判斷複核是否完成**，必須有藥師的明確表示。需要的資料：

| 資料 | 預設 |
|---|---|
| 複核了哪些頁 | 無預設，一定要有 |
| 複核者 | 「藥局衛教助手製作者」 |
| 複核日期 | 今天 |
| 複核依據與版本 | 符合第 2 步「快速相符」時：「藥師在本對話確認的 `<CR編號>` 版本」 |
| 頁面是否顯示「審閱狀態」 | 不顯示 |

藥師沒另外指定就照預設，**不再反問**。不符合「快速相符」、又沒有提供依據與版本時，才停下來問。

## 步驟

### 1. 開工
照作業卡 0 第 1 步。

### 2. 確認複核的是目前網站上的版本（登記 CR 之前做）

**快速相符**：藥師在本對話中確認複核的，就是該頁最近一次修改（清冊 `last_updated_cr`，或本對話剛完成、剛推送的 CR）的成果，而且之後沒有再改、`git status --short` 中該頁的圖片、`data/card_content.json`、`data/label_links.json` 都沒有未提交的改動 → **直接算相符**。不需查 git 歷史、不上網搜尋、不比對網站或檔案位元組。

**其他情況**，對每一頁檢查：
1. **找出實際圖片**：在 cards.json 該頁所屬系列的 `steps` 找到圖片路徑（可能是 `.webp`，也可能是 `.png`），不要自己假設副檔名。用這個路徑在 `data/card_content.json` 找到該頁紀錄；找不到就不能登記，回報藥師需要先補逐頁文字。
2. **找出最近一次改到這頁圖文的紀錄**：從清冊 `page-inventory.csv` 該頁的 `last_updated_cr` 開始找；那張 CR 若只改系列設定、沒有記錄素材版本，就用 `git grep -n "page:<頁ID>" docs/project-management/change-requests.csv` 往前找，直到找到記錄素材版本（圖片檔名、文字版本或日期）的 CR 與 evidence。
3. **比對**：藥師複核的版本（定稿檔名、文字版本，或藥師實際看過的網站版本）跟第 2 項找到的版本一致，就算相符。
   - **只憑日期不算相符**：同一天也可能改過版本。
   - 找不到任何素材紀錄（例如很舊的頁），或無法分辨是否一致時：分別找出下列三項**各自最後一次被修改的提交與時間**，取最晚的一個當作「目前版本」，請藥師確認他看的是不是這一版：
     - 圖片：`git log -1 --format="%h %ad" --date=iso -- <實際圖片路徑>`
     - 逐頁文字：`data/card_content.json` 裡**該頁那一筆紀錄**最後一次內容有變的提交（整個檔案的紀錄不能直接用，要逐一比對歷史版本中這一筆的內容；可以在 `outputs/` 寫一次性的小程式查）。
     - 仿單：`data/label_links.json` 中以該頁實際圖片路徑為鍵的連結，最後一次有變的提交（方法同上；沒有仿單就略過）。
4. **確認沒有未提交的修改**：`git status --short` 中，這頁的圖片、`data/card_content.json` 或 `data/label_links.json` 不可有尚未提交、又不屬於本次的改動。

相符的頁才列入本次登記。版本不一致、對不到 evidence，或無法判斷的頁，**不登記**，回報藥師：「這頁目前版本與複核版本無法確認相同，需要重新複核或提供版本資訊。」全部都不相符時，不登記 CR，直接回報。

### 3. 登記 CR
照作業卡 0 第 2 步，本卡的欄位：`request_type` 填 `修改既有圖卡`，名稱寫「登記藥師複核」；`related_ids` 列出系列與第 2 步確認相符的頁；evidence 檔名用 `<CR編號>-review-<系列ID>.md`，內容寫：相符的頁（以及排除的頁與原因）、複核者、日期、複核依據與版本、藥師的原話（如「已複核」）。

### 4. 更新逐頁文字（只改第 2 步確認相符的頁）
照作業卡 0 第 5 步的 `data/card_content.json` 規定：`needsMedicalReview` 改為 `false`；只有藥師要求顯示時才加 `reviewStatus`，否則移除舊的 `reviewStatus`。其他欄位（文字、日期、來源）一律不動；複核不等於內容更新，`updatedAt` 不改。

要顯示審閱狀態時注意：頁面只有在 `updatedAt` 和 `revisionCredit` 都有值時才會顯示這一行；該頁若設了 `"showEditorialDetails": false` 也不會顯示。遇到這兩種情況，先回報藥師，不要自行改其他欄位。

### 5. 標記完成與建置
照作業卡 0 第 3 步。建置指令：
```powershell
python -B build.py --incremental <複核頁ID> ...
```
不顯示審閱狀態時，建置通常不會改到 HTML，這是正常的。

### 6. 檢查
照作業卡 0 第 6 步；清冊合併後，照作業卡 0 第 5 步的表格填複核欄位，再跑一次 `--propose` 確認零差異。基準比對出現複核相關的錯誤時，打開 `outputs/mgmt-after.json` 找出原因並回報，不要為了通過而改人工欄位。

本卡的**頁面確認**：要顯示審閱狀態，或移除了舊的審閱狀態時，開啟頁面確認顯示正確；其他情況不必開頁面。

### 7. 回報
照作業卡 0 第 8 步，另外列出：登記了哪些頁、複核者與日期、頁面是否顯示審閱狀態。
