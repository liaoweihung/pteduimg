1. 開始前讀本檔、JSON 歷史及最近證據；先確認報表資源、資料截止、日期窗、搜尋類型、裝置與國家篩選。
2. 實際執行手動提交時，逐頁追加 `manual_submissions`，記完整 URL、cohort、台灣日期、已知時間、提交前狀態、實際成功／失敗結果與證據。只是建議、加入 sitemap、即時測試或按下按鈕但尚無結果，都不能記成提交成功。本規則不授權自動提交。
3. 每次實際取得資料後，追加有唯一 ID 的 `observations` 和日期化證據；同一天有新報表／期間／測試也保留不同觀測。完全相同的資料來源與期間可只追加檢查時間及 unchanged，避免重複算資料。不得覆蓋提交歷史或前期基準。
4. 每頁記索引的證據種類、觀測時間、報表資料日與上次檢索日；沒有逐頁證據就寫未取得。首次「觀察到」收錄只代表已知上界，不宣稱精確首次索引日。索引示例缺席或成效表無列，不自動判定未索引或零曝光。
5. 成效記期間起訖、曝光、點擊、CTR、平均排名及主要／新增 query；`null` 表示未取得。CTR 用點擊除以曝光，曝光 0 時為 null；保留 UI 四捨五入值但與計算值標示分開。彙總不直接平均各頁 CTR／排名，不強制頁面／query 加總等於資源總數。GA4 工作階段另列，不能和 GSC 點擊混用。
6. 保留 8/29 五頁與原 21 頁自然等待組；9/6 青春痘六頁是另一批。JSON-LD 第一批 10、第二批 25、第三批 25 各自保留名單與部署證據／窗口，不能因名稱相似自行分派。第二批固定前窗 9/3–9/30、部署日 10/1 排除、後窗 10/2–10/29；完整資料不足先保留 baseline。三個網站資訊頁另組，不能當作未受其他更新影響的乾淨對照。
7. AI／AEO 記平台、模式、日期、問題原文、語言／地區、是否找到及是否明確引用完整 URL；未實測為 null。GSC AI 報表只是該報表的觀測，不替代 ChatGPT 或 Google AI 回答逐一引用的證據。觀測與可能原因分開寫。
8. 更新總控台 SEO/AEO 列與最新證據連結；保留其他日期快照、人工欄位及未完成事項，不因技術測試／少量曝光把全站標成通過。資料無法取得時也追加受阻觀測，寫原因；不得以零補缺。
